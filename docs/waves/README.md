# الموجات: جلسة رئيسية واحدة تدير المراحل

**هذا المرجع الوحيد لتشغيل المراحل:** كيف تبدأ الموجة، ومن ينفّذ مراحلها، ومتى تتوقف الجلسة لتسألك، وكيف تُدمج النتائج. أما قواعد العمل نفسها (التحقق والفحوص والقرارات وGit والتصميم قبل الواجهة) ففي [AGENTS.md](../../AGENTS.md)، وتفاصيل كل مرحلة في ملفها تحت [docs/phases/](../phases/README.md). وهذا الملف لا يكرر شيئًا منهما.

## 1. الفكرة

**تتعامل مع جلسة واحدة فقط: الجلسة الرئيسية** على المجلد الأصلي `/Volumes/iSltanXx/Projects/AYAR`. تقول لها «ابدأ الموجة X»، فتتولى كل شيء:

1. تحسم قرارات البدء بنفسها بتفويضك (ORG-13)، وتسألك دفعة واحدة عمّا بقي لك منها.
2. تجهّز لكل مرحلة مستقلة مجلد عمل وفرعًا خاصين بها.
3. توزّع المراحل على وكلاء يعملون بالتوازي، كل وكيل في مجلده وحده.
4. تتابعهم، وتنقل إليك ما يحتاج قرارك أو اعتمادك أو إذنك، ثم تعيد إليهم جوابك.
5. تتحقق من كل تسليم آليًا، وتدمجه، وتشغّل فحوص التكامل، وتحدّث السجلات والصفحة، وتدفع إلى GitHub.
6. تسلّمك خلاصة الموجة، وتتوقف قبل الموجة التالية.

لا تفتح جلسات أخرى، ولا تبحث عن مجلدات، ولا تختار نماذج، ولا تطلب الدمج بأمر منفصل.

| الأمر | أين | ما يحدث |
|---|---|---|
| «ابدأ الموجة X» | الجلسة الرئيسية | بروتوكول القسم 7 كاملًا |
| «تابع الموجة X» | الجلسة الرئيسية | البروتوكول نفسه: يكمل ما توقف، ولا يعيد ما أُنجز. يُستعمل بعد جوابك عن سؤال، أو بعد إغلاق الجلسة وفتح أخرى |
| «ما الحالة؟» | أي جلسة | جرد للقراءة فقط، وجواب بالموجة الحالية وما ينتظرك |

والأمران الأولان إجراء واحد قابل للإعادة: لا يكرر تجهيزًا ولا تكليفًا ولا دمجًا تم.

## 4. مجلدات العمل والفروع: مسؤولية الجلسة الرئيسية

| البند | القاعدة |
|---|---|
| المجلد | `/Volumes/iSltanXx/Projects/AYAR-wt/<ID>`، مثل `AYAR-wt/DEV-3` |
| الفرع | `phase/<ID>`، يتفرع من `main` بعد دمج تبعيات المرحلة |
| الإنشاء | `git -C /Volumes/iSltanXx/Projects/AYAR worktree add /Volumes/iSltanXx/Projects/AYAR-wt/<ID> -b phase/<ID> main`، أو دون `-b` إن كان الفرع موجودًا |
| النطاق | حقل `scope` في ملف المرحلة: المسارات التي يكتب فيها وكيلها، ويُضاف إليها دائمًا ملفها وملف تسليمها |
| الإزالة | بعد الدمج والوسم والدفع فقط: `git worktree remove` ثم `git branch -d` دون إجبار، فيرفضان عند وجود ما لم يُحفظ أو يُدمج |

**قواعد لا تُكسر:**
- **لا مساس بجلسة جارية:** قبل أي عمل في مجلد مرحلة، تعرف الجلسة الرئيسية الجلسات المفتوحة ومجلداتها (`list_sessions`، حقل `cwd`). المجلد الذي تعمل فيه جلسة يدوية لا يُحدَّث ولا يُكلَّف به وكيل، وتُذكر مرحلته في الخلاصة «جارية يدويًا».
- **لا مساس بعمل غير مدمج:** لا تبديل فرع، ولا تراجع، ولا حذف لمجلد أو فرع فيه commits لم تُدمج أو تغييرات لم تُلتزم.
- **التحديث السريع وحده:** مجلد مجهّز بلا عمل، ثم تقدم `main`، يُحدَّث بـ `git merge --ff-only main` إن كان نظيفًا ولا جلسة عليه.
- **مجلد غريب** (لم تنشئه الجلسة الرئيسية، مثل مجلدات التطبيق تحت `.claude/worktrees/`) يُترك كما هو ويُذكر للمالك.

## 5. وكيل المرحلة

تكلّف الجلسة الرئيسية الوكيل بأداة الوكلاء في الخلفية، بالنموذج والجهد في ملف المرحلة (القسم 9)، وبهذا النص **حرفيًا** مع ملء ما بين القوسين:

```text
أنت وكيل المرحلة <ID> في مشروع عِيَار AYAR، تكلّفك الجلسة الرئيسية.
- مجلدك الوحيد: /Volumes/iSltanXx/Projects/AYAR-wt/<ID> على الفرع phase/<ID>. ابدأ كل أمر Bash بـ cd /Volumes/iSltanXx/Projects/AYAR-wt/<ID> &&، واقرأ واكتب بمسارات مطلقة داخله فقط. لا تلمس المجلد الأصلي ولا أي مجلد آخر، ولا تبدّل الفرع، ولا تدمج، ولا تدفع، ولا تنشر صفحة المراحل.
- المهمة: «<ابدأ | تابع> <مرحلة التطوير | مرحلة التصميم> <N>». اقرأ AGENTS.md ثم ملف المرحلة، واتبع بروتوكول AGENTS.md القسم 3.
- معطيات من المالك سلفًا: <الأجوبة والاعتمادات ذات الصلة، أو «لا شيء»>.
- لا تستطيع سؤال المالك. إن احتجت قرارًا أو اعتمادًا أو إذنًا أو يده، أو بلغت عائقًا مثبتًا: التزم ما أنجزته، وحدّث قسم التقدم وحالة المرحلة (awaiting-owner أو blocked) وسطر owner_request في واجهتها بما تحتاجه موجزًا، ثم أنهِ عملك بالتقرير أدناه.
- عند تحقق معايير الإغلاق: نظّف ما أنشأته أو نزّلته وفق AGENTS.md القسم 10، ثم سلّم وفق AGENTS.md 3.4، ثم أنهِ عملك بالتقرير أدناه.

تقريرك الأخير، بهذه الأسطر أولًا:
الحالة: delivered | awaiting-owner | blocked
المطلوب من المالك: <السؤال بخياراته وتوصيتك، أو ما يُعرض للاعتماد بروابطه ولقطاته، أو «لا شيء»>
آخر commit: <hash>
ثم ملخص قصير بما أُنجز وما اختُبر وما نُظّف.
```

**ما يعود من الوكيل** ثلاث حالات فقط: «سُلّمت» بملف تسليم (القسم 6)، أو «تنتظر المالك» بسؤال محدد، أو «معطّلة» بعائق مثبت. وفي الحالتين الأخيرتين يكون عمله ملتزمًا وقسم تقدمه محدثًا، فيمكن استئنافه بالوكيل نفسه أو بوكيل جديد بأمر «تابع».

## 7. بروتوكول الجلسة الرئيسية: «ابدأ الموجة X» أو «تابع الموجة X»

> النموذج المقترح للجلسة الرئيسية: Claude Opus 5.5 بجهد high. عملها تنسيق ودمج وحل تعارضات أكثر منه تنفيذًا.

**0. المكان والسلامة.** أنت في المجلد الأصلي على `main`، والشجرة نظيفة. وإلا توقف وأبلغ المالك بالسبب. ثم اعرف الجلسات المفتوحة ومجلداتها (القسم 4).

**1. الجرد** (قراءة فقط):

```bash
git fetch origin && git status && git log --oneline -1 origin/main
git worktree list && git branch --list 'phase/*' && git tag -l '*-closed'
/opt/homebrew/bin/node tools/dashboard/build.mjs --check
```

صنّف كل مرحلة في الموجات حتى X: مغلقة، أو مسلَّمة تنتظر الدمج، أو قيد العمل (وكيل أو جلسة يدوية)، أو تنتظر المالك، أو معطّلة، أو متاحة، أو تنتظر تبعية.

**2. المسلَّم من قبل:** كل مرحلة مسلَّمة لم تُدمج (من موجة سابقة أو انقطاع) تمر بالخطوة 6 الآن.

**3. قرارات البدء:** اجمع كل `owner_gates` غير المحسوم لمراحل الموجة المتاحة، وكل `owner_inputs` يمكن معرفته سلفًا (مثل E-15 وE-17 لـ DEV-2)، ثم:
- **ما حالته «مفوَّض»** في `decisions.md` تحسمه بنفسك (ORG-13)، بتوصية الخطة ما لم يظهر دليل يخالفها. وسجّله «محسوم» بسببه، ومصدره «الجلسة الرئيسية بتفويض المالك»، والتزمه قبل التجهيز: `docs(decisions): حسم <المعرّف> بتفويض المالك`.
- **وما حالته «مفتوح»** (باقٍ للمالك) اجمعه في سؤال واحد بخياراته وتوصيتك، والتزم الجواب: `docs(decisions): جواب المالك عن <المعرّف>`. وما بقي منه بلا جواب تبقى مرحلته «تنتظر قرارك»، وتسير بقية الموجة.

**4. التجهيز:** لكل مرحلة متاحة في الموجات حتى X (تبعياتها مغلقة موسومة، وبوابات تصميمها معتمدة، وقرارات بدئها محسومة): أنشئ مجلدها وفرعها، أو حدّث القائم بالقواعد في القسم 4.

**5. التكليف:** لكل مرحلة جُهّزت ولا يعمل عليها أحد: وكيل في الخلفية بنص القسم 5 («ابدأ» لمرحلة لم تبدأ، و«تابع» لمرحلة فيها عمل أو حالتها awaiting-owner أو blocked بعد فكّ عائقها). وإن تعذّر الوكلاء، فنفّذ المراحل بنفسك بالتتابع (القسم 2). ثم ولّد الصفحة وانشرها لتظهر المراحل «قيد العمل».

**6. المتابعة:** كلما عاد وكيل:
- **«سُلّمت»:** `verify.mjs <ID>`. فإن خرج بـ 0، فادمج المرحلة الآن:
  1. `git merge --no-ff --no-commit phase/<ID>`. والتعارض يُحل دون إسقاط عمل أي طرف: السجلات تُحفظ فيها إضافات الطرفين، وملف القفل يُعاد توليده، والشيفرة تُحل بمعناها. وإن لم يُحل دون تغيير مقصد المرحلة: `git merge --abort` وعائق `BLK-WAVE<X>-NN`.
  2. **فحوص التكامل المتأثرة** على شجرة الدمج: بصمات الخطة والروابط النسبية دائمًا، وبناء الحزم المتأثرة وأنواعها وتدقيقها واختباراتها إن مسّ الدمج شيفرة، والحزمة الكاملة إن تغيّر عقد مشترك أو التقت مرحلتان في حزمة.
  3. إن نجحت: `git commit -m "phase(<ID>): دمج المرحلة المسلَّمة"`، ثم `build.mjs --check`. وإن فشلت بخلل في عمل المرحلة: `git merge --abort`، وعائق `BLK-WAVE<X>-NN` بالفحص وخرجه، ثم كلّف الوكيل بـ «تابع» مع سبب الإعادة.
  4. **الإغلاق:** ملف المرحلة `status: closed` و`status_date` و`closing_commit` (الحقل `head` في التسليم)، ونقل التسليم إلى السجلات: التقدم، والتتبع، والقرارات، والبنود المحسومة، وأجوبة المالك، والتبعيات، والعوائق. ثم commit `phase(<ID>): إغلاق بعد الدمج`، والوسم `git tag -a <ID>-closed -m "<ID> مغلقة"`، والدفع `git push origin main --follow-tags`، وإزالة المجلد والفرع (القسم 4).
  5. **التنظيف بعد الإغلاق** (AGENTS.md القسم 10): احذف ما في قسم «التنظيف» بالتسليم «يُحذف بعد الإغلاق». وتحقق ألا يبقى للمرحلة مجلد مؤقت ولا عملية ولا وظيفة launchd. وما «ينتظر المالك» اجمعه في سؤال واحد في نهاية الموجة.
  - وإن خرج `verify.mjs` بـ 1، فأعد الوكيل بـ «تابع» مع ما ينقص. وبـ 3، فانقل عوائق المرحلة إلى `blockers.md` وعاملها كـ «معطّلة».
- **«تنتظر المالك»:** إن كان المطلوب قرارًا مفوَّضًا (ORG-13)، فاحسمه، وسجّله والتزمه، ثم أعد الوكيل دون سؤال المالك. وإلا فتوقف واسأله (القسم 8). وحين يجيب، سجّل جوابه وأعده إلى الوكيل نفسه برسالة متابعة، أو إلى وكيل جديد بـ «تابع» إن تعذّر الأول.
- **«معطّلة»:** سجّل العائق في `blockers.md` والتزمه، وأبلغ المالك بما يلزم لفكّه، ولا تدمج المرحلة. وتستمر بقية الموجة.
- **انقطاع الوكيل دون تقرير:** افحص مجلده وقسم تقدمه، وكلّف وكيلًا جديدًا بـ «تابع». وإن تكرر الانقطاع، فعائق مثبت بخرجه.

وبعد كل حدث يغيّر حالة مرحلة: أعد توليد الصفحة ونشرها.

**7. نهاية الموجة:** حين تكون كل مرحلة في الموجة مغلقة، أو معطّلة، أو تنتظر قرارًا لا يُكمل دونه: قيد «الموجة X — خلاصة» في `progress.md` (ما دُمج، والفحوص ونتائجها، وما أُعيد أو تعطّل، وما ينتظر، والتنظيف: ما أُزيل وما أُبقي وسببه، والأسلوب: متوازٍ أو متتابع)، ثم commit ودفع، ثم الصفحة، ثم الخلاصة للمالك. **ثم توقف. لا تبدأ الموجة التالية حتى يطلبها.**

```text
## الموجة X · <مكتملة | جزئية | معطّلة>
- دُمج: <ID ← commit، الوسم> (لكل مرحلة سطر)
- فحوص التكامل: <الفحص> → <النتيجة>
- لم يُدمج ولماذا: …
- حُسم بتفويضك: <المعرّف ← القرار وسببه> (أو «لا شيء»)
- التنظيف: أُزيل <ما وحجمه> · أُبقي <ما وسببه> (أو «لا شيء»)
- يحتاجك: <اعتماد أو إذن أو ما بقي لك، ومنه ما شُكّ في حذفه>
- الأسلوب: <وكلاء بالتوازي | تنفيذ متتابع> · النماذج المستخدمة: …
- التالي: «ابدأ الموجة X+1» حين <الشرط>، أو «تابع الموجة X» بعد <الجواب>
```

## 8. متى تتوقف الجلسة الرئيسية لتسألك

تتوقف وتسألك، والوكلاء الآخرون يواصلون عملهم في الخلفية، في هذه الحالات فقط:

| الحالة | ماذا تعرض عليك |
|---|---|
| **قرار باقٍ للمالك** (حالته «مفتوح» في `decisions.md`، مثل Q-06 وQ-07) | السؤال بخياراته وأثر كل خيار وتوصيتها. أما القرارات المفوَّضة (ORG-13) فتحسمها الجلسة وتذكرها في الخلاصة |
| **اعتماد مرحلة تصميم** | لقطات ما صُمّم وروابطه في Figma، وما يُطلب اعتماده بالتحديد. ولا تُغلق مرحلة تصميم دون اعتمادك الصريح |
| **إذن لازم** | ما يحتاج يدك أو تفعيل «Enable computer use» (بالتطبيقات والمدة وعدد الخطوات)، أو أي إذن خارج ORG-09 |
| **عائق مثبت** | السبب بدليله، وما جُرّب، وما يلزم لفكّه |
| **نهاية الموجة** | الخلاصة (القسم 7) |

وما عدا ذلك تمضي فيه دون سؤال: القرارات المفوَّضة (ORG-13)، والتجهيز، والتنزيلات وفق ORG-09، والتحقق، والدمج، والفحوص، والسجلات، والدفع، والصفحة. ولا تتجاوز أبدًا شروط التصميم قبل الواجهة، ولا بوابات الفحص، ولا اعتمادك.

## 9. النموذج والجهد

الاقتراح لكل مرحلة في واجهة ملفها (`model` و`effort` و`model_reason`)، والجلسة الرئيسية تمرره عند تكليف الوكيل:

| في ملف المرحلة | عند التكليف |
|---|---|
| Claude Fable 5.1 | النموذج `fable`، والجهد من الملف |
| Claude Opus 5.5 | النموذج `opus`، والجهد من الملف |
| Claude Sonnet 5.5 | النموذج `sonnet`، والجهد من الملف |

**اقتراح لا شرط:** إن رفضت الأداة النموذج المقترح، فالبديل `opus` بجهد `xhigh`، ويُذكر في الخلاصة. والمعايير والفحوص واحدة أيًّا كان النموذج.
